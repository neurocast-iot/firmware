# OSD 水印：配置方案与多平台架构规划

> 适用工程：NeuroCast（mediad 应用 + nc::osd 库）
> 硬件现状：Anyka AK39AV100（arm-ak3918），VI 主/子双通道
> 编写时间：2026-08-28
> 状态：方案已确认待实施（第一阶段已部分落地）

---

## 一、背景与目标

### 1.1 要做什么

前端配置一次时间水印/遮盖图形，设备把它叠加到主、子两路视频上；支持任意主流分辨率（16:9、4:3 等），效果在各通道间保持一致；未来换硬件平台时，上层服务代码零改动。

### 1.2 为什么敢做（前车之鉴取证）

上一代项目 `gw_av100/application/iot_live` 做过同样的事（一套配置多分辨率自动适配），**失败了，最后退化为只支持 16:9**。法医鉴定（源码证据，`OsdManager.cpp`，892 行）：

| 死因 | 证据 | 后果 |
|---|---|---|
| 字号表全是 16 的非整倍数 | `calculateFontSizeByResolution` 映射：360p→20、432p→24、720p→28、1080p→36 | 字库是 16px 点阵，非整倍放大出来的字发虚破边，每个分辨率观感都不一样 |
| 画布从不查上限、不做钳位 | 全文件无 `get_max_rect` 调用 | 小分辨率通道上算出的画布超过 SDK 上限，`ak_osd_create_canvas` 直接失败 |
| 逐分辨率打补丁 | 代码里 `if (320x176)` 特判，用空格填时间格式硬凑对齐 | 适配变成手工补丁，分辨率一多兜不住，只好砍成只支持 16:9 |

结论：失败不是"多分辨率适配"这个思路错了，是漏了字库物理限制和画布上限两条硬件约束。本方案把这两个洞补齐。

### 1.3 本期已踩的坑（设备日志实证）

时间水印上屏失败：创建元素时画布宽高为 0（没调 `.withSize()`），SDK 报
`ak_osd_create_canvas: region_size_width 0 error!`，之后每秒刷 `draw matrix failed`。
教训：**画布尺寸属于"设备内部算"的职责，配置里没有这个字段，代码必须算出来**。

## 二、硬件事实与约束（一切设计的依据）

来源：Anyka SDK 头文件 `ak_osd.h / ak_osd_ex.h`、官方 sample `platform/sample/osd_ex/ak_osd_ex_sample.c`。

| # | 约束 | 说明 |
|---|---|---|
| 1 | 字库是 16px 点阵 | 文件 `/usr/fonts/ak_font_16.bin`，`ak_osd_ex_set_font_file(16, file)` 加载，全局一份 |
| 2 | 显示字号按通道设置 | `ak_osd_ex_set_font_size(channel, size)`；官方 sample 自己就是主=32、子=16 |
| 3 | 字号应取 16 的整倍数 | 点阵放大是像素复制，16/32/48 清晰，非整倍发虚 |
| 4 | 画布上限按通道查 | `ak_osd_get_max_rect(channel_id, &w, &h)`，与该通道当前分辨率绑定，分辨率变了上限就变 |
| 5 | 画布宽高必须非零 | 否则 `ak_osd_create_canvas` 拒绝（本期实测） |
| 6 | 每通道最多 4 个区域 | rect_id 0~3，规划：0=时间，1=标签，2/3=图形 |
| 7 | 颜色是 16 色硬件调色板 | `ak_osd_ex_set_color_table` 设定，只能用表内颜色 |
| 8 | SDK 初始化绑定 VI 会话 | `ak_osd_ex_init2` 必须在相机就绪后调；相机重启前必须 `destroy`、重启后重新 init |
| 9 | 画布内容按 8/16/32 位宽打包 | 库内已封装，服务层不用关心 |

官方 sample 的标准动作（画布钳位）：

```c
ak_osd_ex_get_max_rect(video_chn, &max_w, &max_h);   // 先查上限
width  = (width  > max_w) ? max_w : width;           // 超了就缩进去
height = (height > max_h) ? max_h : height;
```

## 三、配置方案（JSON 定稿）

### 3.1 核心原则

**配置存"意图"（相对值），设备算"像素"（绝对值）。**

用户/前端只管：显不显示、在哪个相对位置、多大档位、什么格式。
设备内部管：像素位置、像素字号、画布宽高、刷新频率——按每个通道的实际分辨率现场换算。

坐标单位统一用**千分比（0~1000 整数）**：不用浮点（云端传输、校验都省事），精度 0.1% 足够。

### 3.2 JSON 结构

```json
{
    "osd": {
        "enabled": true,
        "time": {
            "enabled": true,
            "x": 12,
            "y": 22,
            "size": "medium",
            "format": "YYYY-MM-DD",
            "show_week": false
        },
        "label": {
            "enabled": false,
            "text": "",
            "x": 12,
            "y": 89,
            "size": "medium"
        },
        "shapes": [
            {
                "id": "mask_1",
                "type": "rect",
                "x": 620,
                "y": 150,
                "w": 200,
                "h": 180,
                "color": "black"
            }
        ]
    }
}
```

### 3.3 字段说明

**顶层**

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | bool | OSD 总开关。false 时销毁所有元素、清画布、停刷新线程，SDK 保留 |

**time（时间水印）**

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `enabled` | bool | | 时间水印开关 |
| `x` | int | 0~1000 | 水印左边距，占画面**宽度**的千分比 |
| `y` | int | 0~1000 | 水印上边距，占画面**高度**的千分比 |
| `size` | string | `small` / `medium` / `large` | 字号档位 = 画面高的 30‰ / 44‰ / 60‰，取整到 16 的倍数 |
| `format` | string | `YYYY-MM-DD` / `MM-DD-YYYY` / `Chinese` | 日期格式；时间部分固定 `HH:MM:SS`（24 小时制） |
| `show_week` | bool | | 时间后是否跟"周X" |

**label（自定义文字，本期保留不动）**：结构同 time，多一个 `text` 内容字段。

**shapes（遮盖图形，隐私遮挡用途）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 元素唯一标识，云端管理用 |
| `type` | string | `rect` / `circle` / `ellipse` |
| `x`,`y` | int 0~1000 | rect=左上角；circle/ellipse=中心点。x 相对宽度，y 相对高度 |
| `w`,`h` | int 0~1000 | rect 宽高（相对宽高）；ellipse 的 2rx/2ry |
| `r` | int 0~1000 | circle 半径，相对画面高度 |
| `color` | string | `black/white/red/green/blue/yellow`，限调色板枚举 |

### 3.4 哪些参数用户可改、哪些不能（对标主流）

对照海康/华为 IPC 的"配置 → 图像 → OSD 设置"页：

| 参数 | 用户可改？ | 主流做法 | 本方案 |
|---|---|---|---|
| 显示开关 | 是 | 勾选框 | enabled |
| 位置 | 是 | 拖框/坐标 | x/y 千分比 |
| 日期格式 | 是 | 枚举 | format |
| 星期 | 是 | 勾选 | show_week |
| 字号 | 部分 | 固定或给几档 | size 三档 |
| 字体文件 | 否 | 固件内置 | 设备固定 |
| 画布尺寸 | 否 | 固件内部算 | 设备按字号算 |
| 刷新频率 | 否 | 固件固定每秒 | 固定 1 秒 |
| 颜色 | 部分 | 固定几种色 | 枚举 6 色 |

### 3.5 校验规则（下发时拦截，拒绝比容错好）

1. `x`/`y`/`w`/`h`/`r` 超 0~1000 → 拒绝整段并告警
2. `size` 不在枚举内 → 拒绝
3. `shapes` 数量 > 2 → 拒绝（每通道区域上限 4：时间 1 + 标签 1 + 图形 ≤ 2）
4. 旧格式迁移：现有像素版 `x/y/font_size` 按 1280x720 基准换算成千分比，加载时自动迁移，云端下发新格式后覆盖

## 四、换算与钳位规则（设备侧，所有分辨率共用一段代码）

### 4.1 换算公式（每个通道独立执行）

设通道实际分辨率 W×H，配置千分值 v：

```
像素位置:  px = v_x × W / 1000        py = v_y × H / 1000
图形尺寸:  pw = v_w × W / 1000        ph = v_h × H / 1000
文字字号:  raw = H × 档位比例          font = snap16(raw)，最小 16（按画面高度算）
文本画布宽: cw = 字宽单位数 × font / 2 + 4
            字宽单位数：ASCII 算 1，中文等多字节字算 2（按 UTF-8 数"字"，
            续字节不重复计）；末尾 4 像素是边缘保护（kTextEdgePadPx，
            防最后一个字被裁；留宽了贴右摆放时可见文字离右边缘远）
画布高:    ch = font + 8               （8 像素留白在底部，文字贴画布顶边画）
```

`snap16`：就近取 16 的整倍数档位（16/32/48/64），公式：
`font = floor((raw + 8) / 16) × 16`。
注意是就近不是向上：如 432 高、medium 档，raw=19 → 16（向上取整会得 32，
字宽差一倍，贴边坐标全错——前端预览必须用同一个公式）。

### 4.2 两道钳位（旧项目失败的补洞点，强制执行）

1. **分辨率钳位**：`px + cw ≤ W`、`py + ch ≤ H`，超了就把位置往回缩
2. **画布上限钳位**：相机就绪后调 `OsdSdkManager::getMaxRectSize(chn, &mw, &mh)`，`cw = min(cw, mw)`、`ch = min(ch, mh)`；若被钳位，打一条日志说明

两道钳位都通过才调 `.withSize()` 建元素。**任何分辨率都不写特判分支**（区别于旧项目的补丁式适配）。

### 4.3 前端预览对齐规则（前后端契约，改任何一条都要同步前端）

1. **预览画布逻辑尺寸 = 设备通道分辨率**（如 768×432），设备公式 1:1 套用，
   CSS 只负责视觉缩放；禁止把预览画布的像素坐标存进配置（换分辨率就错位）
2. **字号**：与设备同公式 `floor((H × 档位‰ / 1000 + 8) / 16) × 16`，最小 16。
   取整方向必须一致：向上取整在分叉值上字号差一倍（432 高：16 vs 32）
3. **文字占宽** = 字数 × 字号 / 2（ASCII 算 1 字、中文算 2 字），
   禁止用浏览器 measureText（比例字体，量出来差 5% 以上）
4. **贴右坐标**：`x = 画面宽 − 字宽 − 4`（这个 4 与设备 kTextEdgePadPx 同源）
5. **垂直对齐**：文字贴元素框顶边画（textBaseline="top"），不做垂直居中；
   框高 = 字号 + 8，8 像素是底部留白——居中画会比设备偏低 4 像素以上
6. **贴边坐标与分辨率绑定**：字号按画面高度算且取 16 整倍，不随宽度等比缩放，
   旧分辨率算好的贴边坐标换分辨率后必然不贴边，切换分辨率后必须重算

### 4.4 换算示例（同一份配置，size=medium，x=12，y=22）

| 通道分辨率 | 像素位置 | 字号 | 说明 |
|---|---|---|---|
| 1280x720（16:9） | (15, 15) | 32px | 当前设备配置 |
| 1920x1080（16:9） | (23, 23) | 48px | 视觉占比一致 |
| 640x480（4:3） | (7, 10) | 16px（21→就近取档） | 相对位置一致 |

## 五、多通道一致性设计

### 5.1 主/子通道效果一致怎么保证

- 两通道拍同一个场景（同一 sensor），归一化坐标在两路上覆盖**同一片场景区域**——一致性的准确定义是"盖住的地方一样"，不是像素一样
- 主副同为 16:9（或同为 4:3）时：换算结果是像素级一致
- 混合比例时（如 16:9 主 + 4:3 子）：相对位置一致、视觉占比一致；圆形在像素上可能轻微变椭圆（x 按宽度比例、y 按高度比例各自放大），但覆盖的场景范围不变

**不要求主副通道强制同比例**——主流做法（海康/大华/华为）就是一份 OSD 配置、位置一次设置、固件自动应用到所有码流，不强制比例一致；多数产品的子码流本来就是主码流等比缩小，天然规避。

### 5.2 用户不需要为每种分辨率各配一套

| 方案 | 问题 |
|---|---|
| 用户按分辨率各配一套 | 前端得先知道设备分辨率才能出表单；分辨率热更波及 OSD 配置；云端模板按分辨率组合维护，复杂度爆炸 |
| **一套意图配置 + 设备翻译（本方案）** | 用户只表达"左上角一点、中等大小"；设备拿得到每个通道的实际分辨率，换算发生在相机就绪/重启回调里，分辨率热更自动重算，配置一个字不用动 |

业内证据：Frigate 的遮罩编辑器让用户在画面上点多边形，配置保存**相对坐标（0~1）**，任意分辨率生效（docs.frigate.video/configuration/masks）。

## 六、生命周期与运行时行为

### 6.1 服务接口（与 SnapshotService/RecordService 同一范式）

```
start(cfg, mainChn, subChn)       相机就绪后：按 enabled 初始化 + 建元素
apply(cfg, mainChn, subChn)       配置热更：true→false 清元素；否则重建
pauseForRestart()                 相机重启前：销毁元素 + 销毁 SDK
resumeAfterRestart(cfg, ...)      重启成功后：重新 init + 重建
stop()                            进程退出
```

编排方在 `App.cpp`（配置监听器 + 相机生命周期钩子），服务不主动去拉配置——单向数据流。

### 6.2 刷新线程规则

- **只有时间元素存在才起刷新线程**，其他元素零线程开销
- 每秒一拍：生成时间串 → `setTimeText()` 喂给元素 → `redrawElement()` 重绘
- **契约（库设计如此）**：`TimeElement::draw()` 不读系统时钟，上层必须每秒喂时间，不喂就是空白
- 停线程的函数不能持有服务锁调用（刷新线程循环内要取锁，会死锁）

### 6.3 与相机重启的联动

SDK 初始化绑定 VI 会话：重启前 `OsdSdkManager::destroy()`（画布随会话消失，不用逐个销毁），重启成功后重新 `init()` + 按新分辨率重建元素。分辨率热更 = 相机重启流程的一部分，OSD 自动跟上。

## 七、多平台架构规划（对齐相机的做法）

### 7.1 相机是怎么做的（参照系）

```
apps/mediad  →  libs/camera（CameraDriver 接口，平台无关）
                     ↑ 编译期按 NC_CAMERA_VENDOR 选择
              pal/backends/anyka-av100   ak_vi_* / ak_venc_* 只在这里出现
```

### 7.2 OSD 现状（已确认的代码事实）

- `pal/include/pal/osd_backend.h`：`IOsdBackend` 接口**已定义**（Init/Deinit/CreateRegion/SetPalette/DrawBitmap/Commit/SyncToVi/GetMaxSize）
- `pal/backends/anyka-av100/osd_backend_anyka.cpp`：**空壳**（全部 NOT IMPLEMENTED，等接线）
- `pal/backends/linux-generic/osd_backend_soft.cpp`：软件桩（打印日志）
- `libs/osd`：保真迁入，当前直连 `ak_osd_*`，是"只依赖 pal"规则的**已知例外**（libs/CMakeLists.txt 有门控注释，仅 anyka 平台编译）
- `pal/CMakeLists.txt`：按 `NC_PLATFORM` 选择唯一 backend（开闭原则，新平台加目录+分支即可）

### 7.3 目标架构（与相机完全同构）

```
apps/mediad → libs/osd（平台无关：元素模型 + 点阵栅格化 + 时间喂给）
                    ↓ 只依赖接口
              pal::IOsdBackend（平台相关：画布创建/位图上屏/调色板/字体/同步）
                    ↑ 编译期按平台选择
        anyka-av100: ak_osd_* / ak_osd_ex_*
        linux-generic: 软件模拟（内存画布 + 落图验证）
        <新平台>: 新增 backend 目录，上层零改动
```

### 7.4 分阶段落地

| 阶段 | 内容 | 状态 |
|---|---|---|
| 一 | enabled 启停、时间喂给、重启联动、刷新线程治理 | 已完成，编译通过 |
| 二 | 配置升级：千分比归一化 + 字号档位 + 钳位 + 画布修复 + 图形换算 | **已完成，编译通过，待设备验证** |
| 三 | PAL 下沉：`IOsdBackend` 补齐 DrawText/查询接口 → anyka 后端实现 → `libs/osd` 拆除 `ak_*` 直调、解除平台门控 → linux-generic 软件后端可用于宿主机验证 | 换平台前提，接口已就位 |

阶段三完成后，`libs/osd` 与 `libs/camera` 达到同样的平台无关程度，换平台时只需写一个新后端。

## 八、异常与恢复策略

| 异常 | 表现 | 处理 |
|---|---|---|
| 画布创建失败 | `create_canvas` 返回错 | 记错、跳过该元素，其他元素继续；不重试轰炸 |
| 坐标/尺寸非法 | 校验阶段拦截 | 拒绝整段配置、日志告警、沿用旧配置 |
| 画布超上限 | 换算阶段发现 | 钳位 + 日志，不失败 |
| 单次重绘失败 | `redrawElement` 返回非 0 | 记日志继续跑，下一秒自动恢复 |
| 相机重启 | VI 会话重建 | pauseForRestart → destroy；成功后 resumeAfterRestart |
| 字体文件缺失 | 库自检报 "Font file does not exist" | 元素创建失败、日志告警（设备出厂保证字体存在） |
| 配置热更中途失败 | 元素重建失败 | 保留旧元素继续工作，不清空已有水印 |
